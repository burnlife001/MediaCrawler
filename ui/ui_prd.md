# MediaCrawler UI 产品需求文档 (PRD)

## 1. 项目概述

### 1.1 背景
当前MediaCrawler项目通过命令行方式运行，需要用户手动修改配置文件并执行命令行指令来进行抖音和小红书的评论提取。为了提升用户体验和降低使用门槛，需要开发一个图形化用户界面(GUI)。

### 1.2 目标
- 提供直观易用的图形化界面
- 支持通过视频分享链接直接提取评论
- 实时显示爬取进度和结果
- 自动保存数据并提供导出功能
- 降低技术门槛，让非技术用户也能轻松使用

## 2. 功能需求

### 2.1 核心功能

#### 2.1.1 平台选择
- **功能描述**: 用户可选择要爬取的平台
- **支持平台**: 抖音(dy)、小红书(xhs)
- **UI组件**: 单选按钮组或下拉选择框
- **默认值**: 抖音

#### 2.1.2 链接输入与解析
- **功能描述**: 用户输入视频分享链接，系统自动解析
- **输入格式**: 
  - 抖音: `https://www.douyin.com/video/{aweme_id}` 或分享链接
  - 小红书: `https://www.xiaohongshu.com/explore/{note_id}` 或分享链接
- **UI组件**: 文本输入框 + 解析按钮
- **验证**: 实时验证链接格式的有效性

#### 2.1.3 爬取配置
- **登录方式**: 
  - 二维码登录(默认)
  - Cookie登录
  - 手机号登录
- **评论设置**:
  - 是否获取评论(默认开启)
  - 是否获取二级评论(默认关闭)
  - 单个视频最大评论数(默认100，可调整)
- **其他设置**:
  - 代理设置(可选)
  - 爬取间隔(默认2秒)

#### 2.1.4 实时进度显示
- **进度条**: 显示整体爬取进度
- **状态信息**: 
  - 当前状态(登录中、解析链接、获取评论等)
  - 已爬取评论数量
  - 预计剩余时间
- **实时预览**: 滚动显示最新爬取的评论内容
- **日志输出**: 显示详细的运行日志

#### 2.1.5 数据管理
- **自动保存**: 爬取缓冲区>=100个时,自动保存为.xlsx文件，然后清缓冲区
- **完成保存**：爬取完成时自动保存为.xlsx文件
- **数据预览**: 表格形式展示爬取结果
- **历史记录**: 保存历史爬取任务和结果

### 2.2 数据输出格式

#### 2.2.1 评论数据字段(参考extract_douyin_data.py)
- **nickname**: 用户昵称
- **content**: 评论内容  
- **aweme_url**: 视频链接
- **home_url**: 用户主页链接

#### 2.2.2 内容数据字段
- **nickname**: 用户昵称
- **user_id**: 用户ID
- **title**: 视频标题
- **aweme_url**: 视频链接
- **video_download_url**: 视频下载链接

## 3. 技术架构

### 3.1 技术选型
- **GUI框架**: Tkinter
- **后端逻辑**: 复用现有MediaCrawler核心代码
- **数据处理**: pandas (Excel导出)
- **异步处理**: asyncio (避免UI阻塞)
- **配置管理**: 动态修改config模块参数（复制一个配置模板，然后config\base_config.py添加到.gitignore）

### 3.2 架构设计
```
UI层 (GUI)
├── 主窗口 (MainWindow)
├── 配置面板 (ConfigPanel)  
├── 进度面板 (ProgressPanel)
└── 结果面板 (ResultPanel)

业务逻辑层 (Business Logic)
├── 链接解析器 (URLParser)
├── 爬虫控制器 (CrawlerController)
├── 数据处理器 (DataProcessor)
└── 配置管理器 (ConfigManager)

数据层 (Data Layer)
├── 现有MediaCrawler核心
├── 数据存储 (JSON/Excel)
└── 配置文件管理
```

### 3.3 核心组件

#### 3.3.1 URLParser (链接解析器)
- 解析抖音/小红书分享链接
- 提取video_id/note_id
- 验证链接有效性

#### 3.3.2 CrawlerController (爬虫控制器)
- 封装现有MediaCrawler逻辑
- 提供异步接口
- 支持进度回调和状态更新

#### 3.3.3 ConfigManager (配置管理器)
- 动态修改config.base_config参数
- 保存用户偏好设置
- 管理登录状态

#### 3.3.4 DataProcessor (数据处理器)
- 实时处理爬取数据
- 格式化输出
- 自动保存和导出

## 6. 风险和限制

### 6.1 技术风险
- GUI框架的跨平台兼容性
- 异步操作的UI响应性
- 大量数据的内存管理

### 6.2 功能限制
- 依赖现有爬虫的稳定性
- 平台反爬机制的影响
- 登录状态的维护

### 6.3 解决方案
- 选择成熟稳定的GUI框架
- 实现合理的数据分页和缓存
- 提供详细的错误提示和处理

## 7. 后续扩展

### 7.1 功能扩展
- 支持批量链接处理
- 添加数据分析和可视化
- 支持更多平台(快手、B站等)
- 添加定时任务功能

### 7.2 性能优化
- 多线程并发爬取
- 智能重试机制
- 数据压缩和存储优化
